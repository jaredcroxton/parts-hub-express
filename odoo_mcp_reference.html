Odoo MCP ConnectorSadeem MCP for Odoo 19. What it is, what it does, what it does not do.

A paid Odoo module that lets Claude sign into ACBG's Odoo and ask it questions. Useful for us while building and maintaining the site. It is not the pipe that feeds stock to the website. That job belongs to Odoo's normal API.

Straight answer

Read this first

You asked whether the MCP server can keep the website's stock list matching Odoo. Here is the split.

What MCP does

Lets Claude read Odoo when a person is in a chat. "What is on hand for HP300 parts?" "Show me products under Manganese with no image." "Did last night's order land?" Claude calls Odoo, answers, done.

What MCP cannot do

Feed the website. At 2am with nobody in a chat, there is no Claude session, so there is no MCP call. The site is a program on a server. It has to talk to Odoo itself, through Odoo's built-in API, on a schedule.

MCP is a protocol for AI assistants to use tools. It is a phone line between Claude and Odoo. The website is not Claude, so it does not get to use that line. Same building, different door.

So the stock list on the site comes from a nightly sync job that calls Odoo's API directly, plus a live stock check at checkout. The MCP connector is how we look inside Odoo while building that job and after, without asking the client for spreadsheets.

What it is

  • Module: sadeem_mcp by Sadeem Cloud (Egypt, trading since 2020). Support at support@sadeem.cloud.
  • Price: USD 23.24 one-time. OPL-1 proprietary licence. Builds for Odoo 17, 18, 19. About 3,500 lines of code. Depends on the Discuss module.
  • What it adds: an MCP endpoint on the Odoo instance at a URL with a random segment unique to the database. Scanners cannot guess it.
  • Sign-in: OAuth 2.1 with PKCE. Each person logs in with their own Odoo account. No API keys, no secrets pasted into URLs. The August 2026 release removed the old API-key method, so older guides online are wrong.
  • Permission tiers: chosen at sign-in. Read only, or Read and Write. Delete is never offered.
  • Draft first: anything Claude creates lands as a draft. A person confirms it in Odoo.

Install and configure

Client side

All of this happens inside ACBG's Odoo. We do not own it. Their admin does these, or gives us an admin login for an hour.

  1. Buy and install sadeem_mcp from the Odoo Apps store.

    Get client IT sign-off first. It is code running inside their ERP.

  2. Settings, Claude AI Connector, toggle Enable MCP Endpoint on. Copy the connector URL it generates.

    Regenerating this URL later kills every connected session. That is the emergency off switch.

  3. Settings, Users and Companies, Users. Create a user for Managed Digital with read access to Inventory and Sales. Tick MCP: Can Connect on it.

    Claude sees exactly what this user sees. Keep it narrow.

  4. Confirm Odoo is served over HTTPS. If it sits behind a reverse proxy, Odoo must run with --proxy-mode.

    Claude refuses to sign in over plain HTTP.

Connect

Our side

From claude.ai

  1. Settings, Connectors, Add custom connector.
  2. Paste the connector URL. Leave OAuth Client ID and Secret blank. The module registers itself.
  3. Connect. Sign in with the Odoo user. Pick Read only.
  4. In a chat, press the plus button and switch the connector on.

Needs Claude Pro, Team, or Enterprise. Free plan cannot add custom connectors.

From Claude Code

Same URL, added as a remote HTTP MCP server. OAuth sign-in completes in the terminal.

claude mcp add --transport http odoo-acbg "https://<odoo-host>/<random-segment>/mcp"

Then run /mcp in an interactive session to authenticate. The exact path suffix is whatever the Odoo settings screen shows. Vendor docs only describe claude.ai, so expect to confirm the path on first connect.

Security

  • Tokens stored as SHA-256 digests only. Refresh tokens rotate on every use. A replayed token revokes the whole session.
  • Every call runs under the signed-in user's Odoo access rights and record rules. Nothing escalates.
  • Odoo's audit trail shows the real user's name. Chatter entries are internal notes, not customer-visible messages.
  • Untick "MCP: Can Connect" on a user and their tokens die on the next request.
  • Regenerate the connector URL and every session disconnects at once.
  • Our rule: connect Read only. Decline Write at sign-in. The website writes orders through the API, not through Claude.

Limits and gotchas

  • It cannot feed the website. Said three times now because it is the one that costs money if misunderstood.
  • Odoo Online almost certainly cannot install it. See the hosting gate.
  • Rate limits still apply. Odoo Online fair use is about one request per second. Keep Claude's queries small and paged.
  • Tools key off standard module names (sale, stock, account). Renamed or custom modules do not surface tools.
  • Stale guides online describe pasting an API key into the URL. That method was removed in August 2026.
  • Claude Pro or above on claude.ai. Free plan cannot add custom connectors.
  • Code on the client's ERP. Their IT signs off, not us.

Free alternatives

  • Odoo's own API, no module. A read-only user with an API key. A small Python tool in tools/ pulls the same data. Works on self-hosted, Odoo.sh, and Odoo Online Custom plan. This is the runtime path anyway, so it exists regardless.
  • Open source MCP servers on our side, pointed at that API. Nothing installs on the client's Odoo. Examples: rosenvladimirov/odoo-claude-mcp, industream/mcp-odoo.

Sadeem wins on convenience and per-user OAuth. The alternatives win when the client will not install third-party code or is on Odoo Online.
